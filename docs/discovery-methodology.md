# Discovery Methodology (overview)

**Document date: 2026-11-24 · Plugin v0.1.0**

The authoritative, operational methodology lives next to the skill at
`plugins/boynton-solution-discovery/skills/solution-discovery/references/discovery-methodology.md`.
This page is a reader's overview.

## Twelve conceptual stages (flexible, not a fixed sequence)
1. Initial intake — open-ended problem capture.
2. Problem understanding — symptoms vs. root causes.
3. Stakeholders and users — only the relevant ones.
4. Current-state analysis — investigate what exists; request materials only when they help.
5. Requirements discovery — functional and non-functional, scaled to the project.
6. Assumptions, risks, dependencies — classified; validation-before-build flagged.
7. Solution exploration — real alternatives with trade-offs; non-software allowed.
8. Technical discovery — only after enough problem understanding; every tech choice justified.
9. Scope and delivery strategy — in/out, MVP vs. future.
10. Discovery readiness review — enough known? what could still change the solution?
11. Solution confirmation — explicit human confirmation; AI never self-approves.
12. Deliverable generation — the six artifacts and the kickoff prompt.

Earlier stages are revisited whenever new information requires it.

## Scenario bias (hints, never mandatory flows)
Replace an app · automate a process · new app · integrate systems · AI-assisted · reporting ·
non-software change. The skill infers the likely type(s) only to ask better questions.

## Principles
- Adaptive over exhaustive. Quality of discovery over quantity of questions.
- Challenge, don't just agree. Separate problem from proposed solution.
- Simplest adequate solution. No enterprise complexity unless warranted.
- Honest about uncertainty. Facts, assumptions, hypotheses, and unknowns stay distinct.
